# COMPLIANCE — `@ua-map/ai-seo` (AI-generated SEO content policy)

This service drafts SEO assets **at scale** with an LLM. AI text is a liability,
not a free lunch: ungated AI SEO content trends toward indistinguishable
mediocrity and, worse, can fabricate facts on a sensitive OSINT/conflict
product. The single most important rule:

> **No AI-generated artifact is indexed without (a) passing the
> hallucination/quality gate and (b) clearing the editorial review gate. For
> YMYL page types and tier-1 locales this means a human native-reviewer
> sign-off — a machine pass can never approve them.**

The code enforces this: `quality-gate.runQualityGate` fails **closed** for YMYL
(`YMYL_PAGE_TYPES`), and `review-gate.routeForReview` forces
`requiresNativeReviewer` for YMYL and tier-1 locales and never returns
`approved` for them automatically.

---

## 1. Grounding — no fabricated facts

- Every generator receives a closed set of `GroundingFact`s and is instructed
  (system guardrail in `generate-common.ts`) to use **only** those facts.
- The quality gate decomposes output and flags:
  - `fabricated_number` — any number/date not present in the evidence;
  - `ungrounded_claim` — a citation to a non-existent fact id;
  - `no_grounding_facts` — generation attempted with zero evidence;
  - `missing_citation` — required citation absent (intros, FAQ, YMYL).
- Intros and FAQ answers **require** a citation (`requireCitation`).
- Source/evidence URLs are preserved into schema.org `citation`.

## 2. YMYL — fail closed

- `safety_advisory` (civilian-safety guidance) is YMYL. On **any** quality issue
  the gate blocks and forces native-reviewer sign-off. We never auto-publish
  safety guidance generated by a model.
- If a new page type touches safety, legal, or medical guidance, add it to
  `YMYL_PAGE_TYPES` in `types.ts`.

## 3. Disclosure & transparency

- Every published artifact carries an `AiDisclosure` (`generatedByAi: true`,
  model id, reviewer, localized notice). The gate flags `disclosure_missing`.
- Disclosure is attached at review-approval time (`ReviewQueue.approve`), with
  en + uk notices by default:
  - en: "Drafted with AI and reviewed by an editor."
  - uk: "Створено за допомогою ШІ та перевірено редактором."
- Surfaces that publish these assets MUST keep the disclosure visible (or in
  page metadata) per platform transparency policy.

## 4. i18n / native review

- Per-locale prompts adapt copy (`locale-variants.ts`), **not** raw machine
  translation; the `adapted` flag + `localeAdaptation` score record this.
- **Tier-1 locales (`en`, `uk`) require native-reviewer sign-off** before index.
  This is the moat: reviewer time, not volume.

## 5. Plagiarism / near-duplicate

- `dedup.ts` runs lexical (shingled Jaccard) + optional semantic (embedding
  cosine) checks against existing pages. A hit raises `near_duplicate` and
  blocks/queues the artifact. This protects against both intra-site
  cannibalization and verbatim lifting from sources.

## 6. Cost discipline

- `cost-tracking.ts` (`CostLedger`) estimates USD per call from token usage and
  the pricing table in `llm.ts`, aggregated per page and per kind, so the team
  can watch the cost/quality trade-off.

## 7. Models & secrets

- House default model is the **latest Claude** (`DEFAULT_MODEL`,
  Haiku 4.x for high-volume drafting); Sonnet/Opus available via pricing table.
  No legacy model ids are hardcoded.
- **No secrets in code.** The Anthropic adapter reads the API key from
  `process.env.ANTHROPIC_API_KEY` and throws if unset. Provider coupling is
  loose: any `LLMBackend` may be injected (the future
  `integrations/llm-providers`, the bundled adapter, or `StubBackend`).

## 8. Search-engine ToS

- Generated copy is for the platform's own pages; we do not auto-submit spam,
  cloak, or generate doorway pages. The editorial gate is the backstop. Respect
  Google's spam policies (scaled-content abuse): every indexed page must add
  genuine, reviewed value.
